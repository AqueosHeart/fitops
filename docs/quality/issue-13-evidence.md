# Issue #13 quality and production-candidate evidence

Updated: 2026-10-08

This record separates checks already observed from automation or reviews that still need to run. Issue #13 is not complete until its acceptance criteria have evidence from a successful CI run and the remaining review items are resolved or explicitly scoped.

## Verified in this work session

- `npm audit --package-lock-only --audit-level=high` reported zero vulnerabilities across production and development dependencies after updating the pinned Next.js version from 16.3.6 to 16.3.8.
- The clean install reports the pinned ESLint 9.39.5 as deprecated. The lockfile's current React, import, and accessibility ESLint plugins declare peer support only through ESLint 9, so an ESLint 10 major upgrade is deferred until those plugins support it and the lint config can be verified.
- `npm run lint`, `npx tsc --noEmit`, Prisma Client generation, and `npm run build` passed locally. The Next.js 16.3.8 production build listed 42 routes and generated 33 static page entries without a database connection, using placeholder-only local build variables.
- Build artifact size review: Next's root shared JavaScript plus polyfill files total 552,948 raw bytes (six files); `.next/static` totals 814,059 raw bytes (25 files). These are uncompressed build-artifact sizes, not network transfer size or a user-visible performance score.
- The new GitHub Actions workflow is configured to create a fresh PostgreSQL 16 service, apply migrations, seed fictional data, run database/API/constraint/concurrency suites, lint, generate Next.js route types, type-check, audit all dependencies, build, and run the critical browser journey.
- CI's PostgreSQL `trust` authentication is limited to the short-lived GitHub-hosted test service; application secret and demo password are generated randomly, masked, and exported only for that run. They are not repository secrets or production credentials.
- Earlier GitHub Actions runs [37841999623](https://github.com/AqueosHeart/fitops/actions/runs/37841999623) and [37842824345](https://github.com/AqueosHeart/fitops/actions/runs/37842824345) passed the database, lint/type-check, audit, and build stages. The latter exposed a narrow waitlist assertion and invalid trainer `returnTo`; both test issues were corrected before the later complete green run below.
- GitHub Actions run [37844839060](https://github.com/AqueosHeart/fitops/actions/runs/37844839060) passed the complete critical member/admin/trainer-authorization journey, including all three axe scans on the landing page, member bookings, and administrator roster. PostgreSQL suites, lint/type-check, audit, and build also passed in that run.
- A separate CI-only Playwright lab test now collects three fresh Chromium page-load samples at desktop (1440×900) and mobile (390×844) viewports. It checks p75 LCP ≤ 2,500 ms and CLS ≤ 0.1, thresholds currently described as “good” by [web.dev's Core Web Vitals thresholds](https://web.dev/articles/defining-core-web-vitals-thresholds). Each viewport's raw observations and p75 are attached as JSON to the Playwright report. This is an isolated synthetic smoke budget, not field Core Web Vitals or a 75th-percentile user population estimate; CI results are pending.
- Source review of the existing integration suites confirms explicit cases for cross-origin registration and spoofed-host rejection, session invalidation, login throttling/role-safe return paths, booking ownership/IDOR, role boundaries, and no-state-change failures. The PostgreSQL race suite contains ten synchronized contention/rollback cases; the constraint suite contains two rejected-write cases. These suites are configured in CI but were not executed locally in this session.

## Not yet verified

- The local Docker Desktop Linux engine did not respond to a read-only `docker info` query, so no local PostgreSQL-backed tests or browser journey were run against it.
- The initial GitHub Actions run failed type-check because a clean checkout needs `next typegen` before `tsc`; the workflow now includes it. The initial browser run also exposed axe findings, corrected and verified in run 37844839060.
- The first Actions log displayed unmasked, randomly generated test values in step environment metadata. The workflow now masks them before exporting to later steps. Those values belonged only to the ended disposable test job and are not reused or connected to the deployed app.
- The first CI browser run found landing-page text contrast of 4.43–4.45:1 against soft cream backgrounds (below the 4.5:1 AA threshold) and named loading grids with ARIA attributes but no semantic role. The shared muted color is now `#62655b`, locally calculated at 4.86:1 or better on affected backgrounds, and named loading placeholders now use `role="status"`. Run 37844839060 confirms all three axe scans and the complete critical flow pass. Test retries are disabled because this flow mutates seeded participation; each fresh CI job starts from a clean database. CI trace retention is disabled because traces include authenticated request headers/cookies; prior failed-run report artifacts containing traces were deleted.
- The documented read-only trainer UI is not implemented even though the trainer API and design routes exist; an authenticated trainer's server-side `/portal/login` redirect currently points to the missing `/trainer/sessions` page. This feature is outside Issue #13's code scope and is now explicitly tracked in [Issue #19](https://github.com/AqueosHeart/fitops/issues/19), added to FitOps Delivery as a Phase 4, P1, Medium-risk Feature in Backlog. The E2E case tests the existing trainer API role boundary and `/admin` denial; it does not claim trainer UI coverage.
- Synthetic browser performance results for the new desktop/mobile budget are pending CI. INP, real transfer sizes, and field Core Web Vitals remain unmeasured; no user-facing performance score or production-readiness claim is made here.
- Production operations, TLS/public exposure, backup/restore, monitoring, and deployment rollback remain outside the evidence added here and must not be inferred from CI.

## Current automation entry point

`.github/workflows/quality.yml` is the reproducible CI gate. The critical browser journey and performance-budget test are intended to run only against a fresh, disposable, fictional test database; the test member is created with a unique `example.test` address. No live database, credentials, or production records are used by the workflow.
